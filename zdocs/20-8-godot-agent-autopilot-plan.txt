2.2 Vì sao sidecar + plugin

Plugin phải chạy trong editor để dùng object thật, UndoRedo, selection, Inspector,
import và Play. Sidecar chịu phần không nên nhét vào editor: MCP transport, schema,
filesystem atomic, process/job, Git và lưu ledger. Agent Host chịu suy luận/session dài;
sidecar/plugin tuyệt đối không nhúng model key hay tự giả làm AI. Trong phiên Codex/Cursor/
Claude tương tác, chính client đó là Host. R7 unattended dùng host process có provider
adapter, wakeup và context checkpoint; model credential nằm user store, không trong repo.
Nếu sidecar crash, editor vẫn dùng bình thường. Nếu plugin crash, sidecar fail sạch và
không tuyên bố success.

MCP dùng stdio ở biên agent để không mở HTTP public. Plugin kết nối outbound tới
sidecar bằng session descriptor có ACL của user hiện tại; không scan dải port cố
định. Streamable HTTP chỉ thêm ở R9 nếu có nhu cầu, vẫn bind 127.0.0.1.

2.3 Chiến lược reuse — không viết lại bừa

R1 phải audit và spike các dự án MIT hiện hành. Ứng viên chính ban đầu:

  A. satelliteoflove/godot-mcp — ưu tiên: tool gọn, runtime state, input và
     deterministic playtest; đây là ứng viên primary để vendor/reference.
  B. KeeVeeG/godot-mcp — coverage rộng, Editor API + UndoRedo + activity panel;
     dùng làm coverage inventory, tránh bê nguyên 300+ tool nếu schema gây nhiễu.
  C. Beckett Lite — zero-sidecar, validate-before-write, runtime observation;

  D. Sods2/godot-mcp — tham khảo hybrid live-editor/file và test integrations.

Không chạy đồng thời nhiều MCP plugin trong production. Sau R1 chỉ chọn MỘT base
hoặc tự làm phần tối thiểu nếu audit thất bại. Nếu vendor: pin commit SHA, giữ LICENSE,
SBOM, patch queue nhỏ và upstream-sync test. Không dùng `npx -y latest` trong CI/release.

A1. Godot stock trước: không sửa C++ engine khi Gate GX chưa được người tick.

    chặn `..`, symlink/junction escape, device/reserved path và path quá dài.

A9. Chỉ loopback + random 256-bit token + current-user ACL. Không log token/secret;

A10. OWNER_AUTOPILOT được tự quyết trong project nhưng mọi destructive slice phải có

Ledger bền nằm duy nhất ở `%LOCALAPPDATA%/HHGodotAgent/projects/<project_id>/ledger.sqlite`

5. COMMAND CONTRACT, TOOL SURFACE VÀ EVENT

5.1 Command envelope tối thiểu

Client gửi phần intent tối thiểu (không được tự nâng quyền):

  {
    "protocol": "hh-godot-agent/1",
    "command_id": "ULID",
    "method": "godot.node",
    "action": "add",
    "params": {...},
    "precondition": {
      "scene": "res://scenes/main.tscn",
      "scene_hash": "...",
      "target_uid": "...",
      "property_hash": "..."
    },
    "presentation": {"mode":"watch", "duration_ms":250}
  }

Sidecar xác thực connection rồi tự bind `session_id`, `actor`, `project_id`, policy và
capability grant vào command nội bộ. Giá trị client tự nhét vào các field này bị reject;
request không bao giờ được dùng để chuyển EDIT thành OWNER_AUTOPILOT.

Result tối thiểu:

  {
    "ok": true,
    "command_id": "...",
    "changed": true,
    "before": {...summary...},
    "after": {...summary...},
    "postcondition": {"verified":true, "checks":[...]},
    "undo_action": "Agent: node.add Player",
    "evidence": ["artifact://..."],
    "warnings": []
  }

5.2 Công cụ MCP — ít tool, nhiều action có schema

Ưu tiên ít domain tool + action có schema để agent chọn đúng. Con số cuối không hard-code:
R1 đo trên prompt corpus để chọn flat tools, discriminated action union hoặc lazy registry.
Coverage đến từ action registry, không từ việc khoe hàng trăm tên tool. Nhóm bắt buộc:

  capabilities.describe   version/class/property/method/action discovery
  project.*               inspect/settings/input/autoload/plugin/doctor
  scene.*                 create/open/read/save/close/instantiate/dependencies
  node.*                  add/remove/rename/reparent/reorder/duplicate/group/query
  property.*              get/set/batch/reset; Variant/Resource/NodePath codec
  resource.*              create/load/assign/duplicate/edit/save/uid
  signal.*                list/connect/disconnect/inspect
  script.*                read/write/patch/validate/attach/open_at/diagnostics
  asset.*                 import/reimport/move/rename/delete/dependencies/preview
  tilemap.*               tileset/source/terrain/layer/cell/fill/stamp/query
  animation.*             library/animation/track/key/state-machine/preview
  ui.*                    Control/theme/layout/anchor/focus/accessibility query
  editor.*                state/select/focus/main_screen/frame_view/replay/pause
  play.*                  start/stop/restart/debug/status/logs
  input.*                 action/key/mouse/touch/sequence/release_all
  runtime.*               tree/node/state/signal/time/freeze/step/screenshot/perf
  test.*                  define/run/assert/report/evidence/baseline
  export.*                preset/validate/build/cancel/artifacts
  git.*                   status/diff/checkpoint/revert_checkpoint (project-scoped)
  job.*                   status/list/cancel/wait

Mỗi action khai báo side_effect (`read`, `view`, `mutate`, `destructive`, `external`),
undo strategy, timeout, cancellable, required policy, input/output JSON Schema, error
codes và postcondition. CLI/help/MCP schema/contract test sinh từ registry này.

5.3 Stable identity

NodePath và tên có thể đổi. Plugin dùng composite reference: scene UID/path + node
`_hh_agent_uid` + structural fingerprint/path hint. Node được duplicate/instantiate/inherit/
make-local có thể copy metadata, nên save/open scan phải phát hiện collision và sửa trong
UndoRedo trước khi nhận lệnh tiếp. Resource ưu tiên Godot UID nhưng vẫn có hash/path hint
vì built-in resource không phải lúc nào cũng có UID. Nếu identity mâu thuẫn: fail conflict,
không đoán.

5.4 Ledger và crash recovery

Sidecar dùng SQLite ở durable LocalAppData, `journal_mode=WAL`, `synchronous=FULL`, với
trạng thái `received → validated → applying → applied_volatile → verified →
committed_durable/failed/uncertain`. `received/validated/applying` và canonical request
hash phải commit+flush trước khi dispatch tương ứng. Cùng `command_id` nhưng request hash,
bound actor/project/policy khác trả `E_IDEMPOTENCY_CONFLICT`, không trả cached result.

Ledger phân biệt `applied_volatile` với `committed_durable`. Một scene mutation chỉ thành
durable khi save scene/resource thành công, file trên đĩa đọc lại được và disk hash khớp.
Batch/transaction chỉ save một lần cuối; lỗi save phải rollback hoặc restore checkpoint.

Crash ở `applying`/`applied_volatile` không tự chạy lại mù quáng. Khi resume:

  1) đọc postcondition theo stable UID/hash;
  2) nếu đã đúng, đánh committed và trả cached result;
  3) nếu trước-state còn nguyên, apply lại một lần;
  4) nếu cả trước và sau đều không khớp, trả `E_UNCERTAIN`, restore checkpoint hoặc
     mở repair flow; tuyệt đối không báo success.

Ledger là audit/dedup, không cố thay định dạng `.tscn` của Godot bằng document model mới.

5.5 Event stream cho người xem

  action.planned, action.started, selection.changed, overlay.started,
  mutation.committed, postcondition.verified, import.started/completed,
  play.started/stopped, test.assertion, checkpoint.created, action.failed,
  agent.paused/resumed.

Activity Dock hiển thị actor, scene/node, diff ngắn, thời lượng, verify và nút mở evidence.
Secret/value nhạy cảm được redact trước event. Feed không được là nguồn thực thi lại; replay
dùng bản presentation event riêng và không gọi mutation lần hai.

6. PROFILE TỰ CHỦ, AN TOÀN VÀ QUYỀN NGƯỜI DÙNG

6.1 Ba profile

  OBSERVE          chỉ đọc editor/runtime/evidence.
  EDIT             mutate project, destructive cần approve.
  OWNER_AUTOPILOT  mutate/destructive project-scoped tự duyệt sau checkpoint.

Repo này mặc định OWNER_AUTOPILOT theo yêu cầu người dùng. Profile không cấp quyền ra
ngoài project, không tự tiêu tiền và không tự publish.

6.2 Chính sách quyết định không hỏi người

Khi brief không chỉ định chi tiết nhỏ, agent chọn theo thứ tự:

  1) convention Godot và template đã pin;
  2) phương án dễ test/revert nhất;
  3) phương án ít dependency và public API nhất;
  4) phương án có chất lượng game tốt hơn nếu chi phí tương đương.

Assumption ghi vào `.hh-agent/evidence/<run>/assumptions.md`, không chặn tiến trình. Chỉ
E1–E4 ở mục 0.4 bắt buộc cần input/quyền mới từ người; lỗi kỹ thuật có thể chuyển hệ thống
sang safe-stop/repair/critic theo 6.5 mà không mặc định giao việc làm hộ cho người.

6.3 Pause, rollback và review

Toolbar/Dock có Pause đỏ luôn thấy, shortcut được pin. Pause đóng gate mutation ở sidecar
và plugin; job cancellable nhận cancel, job atomic hoàn tất rồi dừng. Người có thể:

  - xem diff/checkpoint;
  - Undo action hiện tại trong Godot;
  - revert checkpoint bằng một lệnh recoverable;
  - chuyển Watch ↔ Fast mà không ảnh hưởng project.

Review mặc định ở cuối milestone, không phải cuối từng WP. Agent vẫn tạo checkpoint nhỏ
để rollback. Gate cần mắt người chỉ là G2 (trải nghiệm xem), G5 (chất lượng game), GX
(fork) và E3/G6 publish/signing; các gate kỹ thuật còn lại tự chốt bằng test + critic.

6.4 Security tối thiểu

  - canonical root + allowlist extension/path; khóa `res://addons/hh_agent/**`,
    `.hh-agent/**`, ledger/session/capability-lock khỏi generic write/delete tools;
  - no arbitrary shell tool; process allowlist chỉ Godot, test runner, exporter, Git;
  - subprocess args là array, không ghép shell string;
  - import asset được kiểm magic/size/decode và quarantine trước res://;
  - runtime test code chỉ có trong debug/test build, bị strip/disable ở release;
  - export filter + artifact scan cấm addon, token, evidence và test runtime vào game build;
  - log/screenshot scrub token, home path, API key và environment secret;
  - dependency audit, license scan, checksum và SBOM ở mỗi release;
  - MCP/server từ upstream phải threat-model trước khi enable OWNER_AUTOPILOT.

6.5 Bảng authority duy nhất

| Tình huống | Hệ thống làm gì | Có cần người ngay? | Ai chốt |
|------------|-----------------|--------------------|---------|
| Assumption nhỏ, phương án kỹ thuật trong scope | tự chọn, ghi evidence, tiếp tục | Không | Agent Host |

9.1 Critical path

  R0-1 → R0-2 → R0-3 → R0-4
       → R1-1 → R1-2 → R1-3 → R1-4 → R1-5/G1
       → R2 registry/transport/router → ledger/policy/read model
       → R3 scene/node/property/script/asset → transaction gauntlet
       → R4 visible/G2
       → R5 2D coverage + R6 runtime self-verify/G3
       → R7 autonomy/G4 → R8 dogfood/G5 → R9 release/G6

R4 không được trì hoãn tới cuối vì “người thấy được agent làm” là yêu cầu sản phẩm,
nhưng presentation không được chặn correctness của R3. R5 và R6 có thể xen kẽ sau khi
R3 primitives ổn: mỗi adapter 2D phải có runtime assertion ngay, không đợi R6 hoàn tất.

9.2 Fan-out khuyến nghị

Sau G1:

  - Agent A: R2-WP1/2 registry + transport.
  - Agent B: R2-WP3 plugin lifecycle trên schema stub đã chốt.
  - Agent C: fixtures/E2E/fault harness, không sửa production router.
  - Agent D: observer UI prototype từ read-only event interface.

Sau R3-WP4:

  - Lane 1: TileMap/physics/navigation.
  - Lane 2: animation/audio/shader.
  - Lane 3: UI/layout/accessibility.
  - Lane 4: runtime/input/time/assertions.

Sau R8-WP1:

  - Gameplay graybox và test critical path.
  - Asset creation/import staging.
  - UI/audio concept + reusable resources.
  - QA xây test manifest từ acceptance.

Chỉ merge khi dependency contract đã versioned. Generated registry/progress table/lockfile
do coordinator cập nhật; agent track gửi patch, không cùng lúc edit. Scene dogfood có thể
tách thành `world.tscn`, `player.tscn`, `ui.tscn`, `actors/*.tscn` để lease độc lập.

9.3 WIP limits

  - tối đa 4 WP code đang in-progress toàn repo;
  - tối đa 1 schema migration và 1 Godot mutation E2E cùng lúc;
  - mỗi agent tối đa 1 WP chính; subtasks chỉ research/test độc lập;
  - một WP >2 ngày hoặc >~800 dòng production phải split trước khi code;
  - không mở milestone mới chỉ để “giữ agent bận” khi invariant/gate đang đỏ.

9.4 Ưu tiên sửa lỗi

  P0: corruption, false success, auth/path escape, mất user work, release leak.
  P1: workflow P0 capability không làm được, undo/recovery sai, self-test false pass.
  P2: visible replay/UX/perf làm chậm nhưng có alternative đúng.
  P3: polish/docs/backlog không chặn game.

P0/P1 luôn chen trước feature mới. Một test bị sửa từ assert feature có sang assert feature
thiếu là reject; gap phải đỏ rõ chứ không biến thành test xanh.

11. ERROR MODEL VÀ OBSERVABILITY
================================================================================

Lỗi tối thiểu, có `code`, `message`, `retryable`, `state`, `evidence`:

  E_AUTH          token/origin/session sai
  E_POLICY        profile/capability không cho phép
  E_PATH          path/root/symlink/reserved violation
  E_SCHEMA        params/protocol/action version invalid
  E_NOT_FOUND     stable identity/path/resource không tồn tại
  E_AMBIGUOUS     UID collision/multiple target, không đoán
  E_CONFLICT      revision/history/fingerprint/base hash/human edit lệch
  E_IDEMPOTENCY_CONFLICT  cùng command_id nhưng canonical request/binding khác
  E_UNSUPPORTED   public semantic capability chưa có, kèm alternative/gap ID
  E_BUSY          import/save/editor transition đang bận, có retry_after
  E_TIMEOUT       deadline, state/cancel outcome rõ
  E_CANCELLED     cancel ở safe-point, partial state/rollback report
  E_VALIDATE      script/import/property/postcondition fail
  E_SAVE          apply volatile nhưng durable save/readback fail
  E_UNVERIFIED    handler không chứng minh postcondition
  E_UNCERTAIN     crash giữa apply, cần reconcile/checkpoint recovery
  E_EXTERNAL      cần E1–E3 hoặc external service fail

Metrics: queue latency, apply time, save/import time, postcondition time, Pause ACK,
reconnect, conflict, retry/dedup, E_UNCERTAIN, editor frame stall, test flake, evidence size.
Mọi metric có run/session/action tags không chứa path/secret thô.
