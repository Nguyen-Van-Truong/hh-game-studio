1. QUYẾT ĐỊNH VÀ PHẠM VI KHÔNG ĐƯỢC ĐỔI NGẦM
================================================================================

1.1 Mục tiêu trải nghiệm

- Góc nhìn side-view 2D platform arena, nhiều tầng, hố chết, vật thể làm cover.
- Trận đấu hỗn loạn nhưng đọc được: chạy, nhảy, crouch, aim lên/xuống, nhặt
  vũ khí, bắn/ném/đấm, knockdown và trở thành người cuối cùng sống.
- Có VS 1P (bot), local VS 2P cùng bàn phím, Stage liên tiếp và Survival.
- Camera bao quát toàn arena; không biến thành top-down hoặc Street Fighter 1v1.
- “Giống nhất” nghĩa là hành vi, nhịp độ, affordance và topology chức năng;
  không có nghĩa sao chép pixel, sprite, mã, âm thanh, screenshot hay bố cục
  tọa độ 1:1 của tác phẩm tham chiếu.

1.2 Phạm vi bản phát hành mục tiêu

Must-have trước V5:

- movement: walk, jump, variable jump, crouch, double-tap sprint, stamina,
  roll, dive, fall/dive behavior, ladder climb, ledge/edge recovery;
- combat: fists, kick/jump-kick, melee weapons, aim hold/release fire,
  directional aim, knockback/knockdown, brief invulnerability, disarm,
  grenade arc/bounce/explosion, friendly-fire rules rõ ràng;
- weapons: pistol, UZI/SMG, shotgun, rifle/long-range, heavy launcher,
  melee variants, grenades/molotov-like original item; data-driven tuning;
- world: destructible glass/wood, throwable/shootable props, explosive
  barrel/container, elevators or moving platforms, doors, ladders, toxic
  hazard, map-specific machinery;
- maps: bốn stage-archetype tương ứng rooftop/warehouse/station/sewer và hai
  VS-archetype bổ sung; tên hiển thị, tile, landmark, art phải nguyên bản;
- modes: VS 1P, local 2P, Stage progression, Survival score/spawn loop;
- presentation: 4+ original fighter identities, readable animation states,
  hit/death feedback, health/stamina/ammo HUD, pause/restart/settings;
- agent workflow: semantic commands only, real Godot window observation,
  runtime input injection, screenshot/assert/repair/checkpoint, no human
  editing in happy path.

Nice-to-have sau V5, không chặn parity gate: online multiplayer, map editor
cho người chơi, C# support, bullet-time nâng cao, ragdoll/gore phức tạp,
console/mobile export, workshop. Không tự mở các mục này giữa WP bắt buộc.

1.3 Những điều cấm

- Không tải, rip, trace, bundle hoặc ship asset/code/audio/SWF/Flash/HTML5
  package/screenshot của Y8, Newgrounds, MythoLogic hay wiki.
- Không dùng “Superfighters”/“Super Fighter” làm tên sản phẩm, title card,
  nhân vật, map name thương mại hoặc metadata phát hành.
- Không fork/sửa C++ Godot; dùng Godot stock 4.7.1-stable đã pin.
- Không đụng `godot/dogfood/kho-bi-an/`, Hoan Hao social, Rust `gs-*` legacy,
  plan G6/GX, hoặc các file Snake ngoài scope.
- Không dùng fixture/teleport/force-kill làm bằng chứng duy nhất cho tính năng
  gameplay; fixture chỉ được dùng để unit-test nhanh và phải có trace thật.
- Không tick WP/gate bằng unit test xanh nếu DoD yêu cầu cửa sổ, replay, build,
  review người hoặc evidence độc lập.

1.4 Nguồn sự thật và đường dẫn

- Plan nền platform: `zdocs/20-8-godot-agent-autopilot-plan.txt`; giữ nguyên

thay đổi kích thước, landmark, tile language, item placement và tên hiển thị.
Nếu muốn phát hành thương mại với layout quá gần, dừng tại V5 và yêu cầu legal
review; agent không tự kết luận “fair use”.

================================================================================
4. KIẾN TRÚC MỤC TIÊU VÀ BẤT BIẾN
================================================================================

4.1 Luồng runtime

`brief → planner → semantic command bus → Godot EditorPlugin → UndoRedo /
atomic file write → runtime process → input trace → snapshot/screenshot /
assert → repair → checkpoint → review package`

Agent được phép dùng API editor, bridge/MCP hiện có và các công cụ Windows để
đọc/ghi trong project. Mọi mutation có ý nghĩa phải đi qua command có schema,
postcondition và command id; không raw-write `.tscn` từ script ngoài plugin,
không giả ACK.

4.2 Quyền và file ownership

- Một writer cho mỗi file tại một thời điểm; scheduler cấp lease có expiry,
  owner và authenticated release. Các thay đổi cùng file phải FIFO.
- `godot/dogfood/superfighters/` là product tree mới; `godot/plugin-project/`
  và `bridge/` là platform tooling, chỉ sửa khi WP ghi rõ.
- Agent không tự sửa plan checkbox. Coordinator là người duy nhất tick và cập
  nhật `CURRENT_VALID_WP` sau Verify + DoD + LOG + critic.
- Mỗi commit chỉ chứa một WP hoặc một nhóm WP đã ghi rõ; loại `snake/`,
  `drive_snake*.py`, `.godot/`, token, cache, build output khỏi commit.

4.3 Invariants V-A1…V-A20

- V-A1: Godot stock 4.7.1-stable; không C++ fork/GDExtension trừ khi owner mở
  gate riêng sau gap report.
- V-A2: mutation semantic, schema versioned, validate trước apply.
- V-A3: UndoRedo hoặc transaction atomic cho thay đổi editor; không partial
  scene/resource khi lỗi.
- V-A4: mọi mutating command có unique `command_id`; retry là idempotent.
- V-A5: ACK chỉ sau postcondition đọc lại từ Godot/runtime.
- V-A6: file path nằm dưới project root; không path traversal/symlink escape.
- V-A7: Godot object chỉ thao tác main thread; runtime/editor tách process.
- V-A8: bridge chỉ loopback + token; secret không vào log/evidence/screenshot.
- V-A9: một writer/file; conflict đóng lane, reconcile rồi mới tiếp tục.
- V-A10: checkpoint trước destructive mutation; rollback thử được.
- V-A11: Play chạy process riêng từ project snapshot; editor không điều khiển
  state runtime bằng biến dùng chung.
- V-A12: pause ưu tiên; khi pause/stop phải drain/cancel an toàn, không mất ACK.
- V-A13: save dùng temp+rename/atomic replace; hash và schema ghi trong manifest.
- V-A14: input trace dùng tick 60 Hz, event down/up rõ ràng, có seed.
- V-A15: physics/combat deterministic trong cùng pin và seed; epsilon ghi rõ.
- V-A16: không dùng teleport/force-kill/fixture-only để chứng minh E2E.
- V-A17: typed GDScript, không warning/error runtime trong official run.
- V-A18: evidence có timestamp, command/trace/hash, repro command và verdict.
- V-A19: không claim feature từ code chưa chạy hoặc ảnh tĩnh chưa đối chiếu.
- V-A20: mọi claim “giống Y8” phải trỏ reference ledger + acceptance case;
  uncertain value phải được gắn `tuning`, không ghi như fact.

4.4 Data model tối thiểu

Tạo resource/data typed cho `FighterState`, `WeaponSpec`, `ArenaSpec`,
`PropSpec`, `MatchRules`, `InputFrame`, `ReplayHeader`, `RunEvidence`. Không
hard-code tuning rải trong nhiều script. Mỗi state có version và serializer;
snapshot không chứa object reference hoặc secret.

4.5 Các lớp gameplay

1. Simulation: fixed 60 Hz, seed, collision/query, event queue.
2. Actor: locomotion/state machine, hitbox/hurtbox, inventory, animation cues.
3. World: tile geometry, one-way surfaces, props, hazards, moving bodies.
4. Match: spawn, teams, scoring, round/mode transitions, pause/restart.
5. Presentation: camera, HUD, audio/VFX, menus, accessibility.
6. Automation: semantic editor actions, runtime input, observation, repair,
   checkpoint and review bundle.

16. DAG, PARALLELISM VÀ QUY TẮC LEASE
================================================================================

16.1 Critical path

`VF0-WP1 → VF0-WP2/VF0-WP3 → VF1-WP1..4 → VF2-WP1..4 → VF3-WP1..4 →
VF4-WP1..5 → VF5-WP1 → VF5-WP2..5 → VF6-WP1..4 → VF7 → VF8 → VF9 → VF10`.

VF2-WP5 có thể chạy sau VF2-WP4 trên collision fixture tạm. VF5-WP6, bot,
presentation và tool adapters chỉ được song song khi file ownership rõ. Không
cho hai agent sửa cùng `fighter.gd`, `game_session.gd`, `maps.gd` hoặc cùng
resource/art manifest; dùng interface/data file riêng rồi một integrator merge.

16.2 Mỗi agent trước khi làm

1. Đọc `AGENTS.md`, bảng đầu file này và WP đầu tiên chưa tick.
2. Kiểm tra `CURRENT_VALID_WP`, git status, baseline hash và active leases.
3. Đọc chỉ invariant/reference mà WP trỏ tới; không mở/sửa WP xa để “tiện”.
4. Ghi plan nội bộ 3–7 bước, nêu file mình sở hữu và command verify.
5. Nếu phát hiện mâu thuẫn requirement, ghi DECISIONS/gap report rồi dừng phần
   lệch; không sửa acceptance âm thầm.

16.3 Trong khi làm

- Ưu tiên test trước cho behavior; giữ thay đổi nhỏ, typed, reversible.
- Mỗi mutation qua semantic adapter; mọi run có `run_id`, `command_id`, seed,
  map/mode và source hash.
- Quan sát cửa sổ thật ở các mốc quan trọng; screenshot chỉ là evidence,
  không thay postcondition đọc từ runtime.
- Khi agent khác bận cùng lane, xếp FIFO hoặc chờ lease; không bypass bằng
  raw-write/file copy.
- Không mở Y8 bằng automation tải package; chỉ quan sát trang/reference hợp lệ.

16.4 Khi kết thúc WP

Agent không tick checkbox. Gửi report theo mẫu:

`WP=<id>; Base=<commit/hash>; Files=<list>; Verify=<exact commands + counts>;
E2E=<run_id/trace/evidence hashes>; Critic=<id/result>; Gaps=<typed list>;
Commit=<hash or uncommitted reason>`

Coordinator chỉ tick khi: dependency xanh, test/real window pass, evidence hash
đủ, no secret, diff sạch, critic độc lập đồng ý và mọi gap được ghi. Một critic
“yes” không override một failing required check.
