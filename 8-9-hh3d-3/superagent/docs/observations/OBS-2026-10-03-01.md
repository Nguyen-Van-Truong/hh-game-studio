## Access and measurement limits

The Y8 page loaded the correct title, but coordinate clicks through its two
nested frames did not activate PLAY. Fractional iframe bounds also caused
some input attempts to be rejected. An explicit 1215×800 viewport gave integer
outer-frame bounds (15,68,855,567); the tool's screenshot was 1200×790, so it
must not be treated as a 1:1 coordinate grid. Reloading and focusing the inner
canvas still did not make the nested coordinate click work.

The successful alternative opened the exact current inner iframe `src` in a
temporary tab in the same browser, retaining all parameters from the Y8 page,
including its referrer and configuration. No URL parameters were synthesized
or decoded and no game internals were read. This tab rendered the same title;
clicking PLAY at (629,630) in its 1280×720 viewport entered the menu. A prior
attempt that omitted parameters loaded a different title and was rejected as
reference evidence. Do not reuse that stripped URL.

Observations below are from the correctly configured frame opened separately.
They still need a normal embedded-page cross-check before final parity. The
frame was not a downloaded package. The only DOM inspection was frame/canvas
rectangles, visible UI structure and the frame's navigation URL.

Input method: documented browser `pressKey` taps and mouse clicks. No known
hold duration, tick scheduling, 60-fps capture or game RNG seed was available.
No frame-level input trace is claimed. Three-sample movement/combat timing is
therefore unavailable. Ten-sample randomness was not collected in this session;
counting discrete visible outcomes does not itself require held input or video.
A sequence of
one Right tap followed by ten further Right taps in the tutorial moved the
fighter only a few visible pixels; this is insufficient for a speed estimate.
Do not interpret failed/short input as an absent mechanic.

## S09: menu and control settings

One live traversal unless a cycle is explicitly stated. Counts have no visual
ambiguity in the inspected panel; this is categorical evidence, not timing.

- Main menu has four entries: one player, two players, tutorial and setup.
- Both player-count entries expose VS, Stage and Survival (three modes each).
- Up/Down changes menu selection, Space accepts, Escape goes back. Main-menu
  Up from the first entry wrapped to setup. Clicking setup text did not open
  it; keyboard navigation did. Do not infer every menu is mouse-operable.
- Setup has four entries: graphics quality, effect quality, sound volume and
  edit controls. Displayed values were High, High and 80%. Quality/volume
  ranges and persistence were not tested.
- Edit controls exposes P1 and P2, Simple/Advanced configuration and a reset
  action. Reset was not executed. Right on the player selector changed P1→P2.
- Simple P1 labels: Up/Down/Left/Right arrows; melee N; shoot M; grenade comma;
  power-up period. Simple P2 labels: W/S/A/D; melee 1; shoot 2; grenade 3;
  power-up 4. These are observed binding labels, not proof of every action.
- P2 Advanced labels distinguish aim/climb-up and jump (both W), aim/climb-down
  and kneel/roll/dive (both S), aim/run-left A, aim/run-right D, then the four
  combat/power keys. Toggle sprint is present and unbound. Advanced was changed
  back to Simple before leaving. No rebind was performed.
