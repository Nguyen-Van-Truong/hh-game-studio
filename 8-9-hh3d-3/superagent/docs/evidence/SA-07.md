# SA-07 — provisional mode-flow slice

This file records an engineering slice only. It is not a Y8 parity result,
owner acceptance, critic signature, or SA-07 checkbox gate.

## Scope

`game/core/classic_mode_rules.gd` now owns deterministic flow state for the
three mode families already observed in the reference inventory: VS, Stage and
Survival. VS accepts the seven observed rule labels (Infinite, First to 3/5/10
and Best of 3/5/10), computes the correct round target, and exposes
ready/playing/round_result/result/paused transitions. Stage starts with the
first of twelve challenge slots unlocked and advances one slot after a P1 win.
Survival increments its wave after a clear and ends on defeat. Unknown modes and
rules fail closed.

`MatchSession` keeps its existing `(seed, opponent)` constructor behavior and
defaults to VS/Infinite. Optional mode/rule arguments are included in its
snapshot and canonical hash, so future menu wiring cannot silently change the
deterministic state. Infinite VS closes the current result overlay, while
finite VS, Stage and Survival preserve a round-result seam for a later menu.
`ClassicSettingsStore` adds schema-checked local graphics/effects/volume,
control and normal-action binding persistence with immutable snapshots and
replacement recovery. It does not expose the reserved special-character
actions. The bootstrap menu now routes keys 1/2/3 through real key events to
VS/Stage/Survival scene instances; round-result overlays accept Enter/R to
continue finite sessions. Pause is routed through `MatchSession` and bot input
history is reset at the same boundary; the HUD reads mode score/stage/wave
state from the immutable snapshot.
