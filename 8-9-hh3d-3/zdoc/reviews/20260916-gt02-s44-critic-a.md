### A2 — P2 reproduced: a read-only consumer still admits a new mutation

Primary location: `studio/host/core/fixture_selector.py:539-548`.
Related paths: `fixture_selector.py:372-386`, `fixture_selector.py:680-710`,
`safe_replace.py:175-176`, and `selector_pipe.py:157-160`.

After a normal successful commit, close and reopen the file root with
`ProtectedFileRoot.reopen_readonly`, then call `load_committed` successfully.
The root is intentionally incapable of further mutation. Nevertheless,
`FixtureSelector.prepare` checks only selector uncertainty/Stop and staging
capacity before appending INTENT. It never checks the consumer's known write
hold. A fresh valid request therefore returns ACCEPTED_PENDING, writes new
blobs, and durably advances SELECT. Only the eventual file replacement detects
`SAFE_REOPEN_REQUIRES_RECONCILIATION`.

Independent native reproduction on the frozen closure produced:

| Observation | Result |
| --- | --- |
| Fresh command admission | ACCEPTED_PENDING / INTENT |
| Added journal events | 4: INTENT, STAGING, STAGED, SELECT |
| Added blob files | 2 |
| Selected generation | 1 -> 2 |
| Consumer readiness | true -> false |
| Actual active file | unchanged, including FileVersion |
| Adoption error | SELECTOR_ADOPTION_UNKNOWN |
| Error cause | SAFE_REOPEN_REQUIRES_RECONCILIATION |
| Pending command lookup | UNKNOWN / SELECTED |

The lower-level write hold works: no forbidden replacement or false COMMITTED
receipt occurred. The bug is admission of work already known to be unsupported.
It consumes bounded persistent capacity and leaves the single-pending selector
stranded instead of returning a no-effect refusal before INTENT. This is also
reachable through the broker's normal new-command dispatch, which calls the
same prepare method; the independent runtime reproduction used the direct
trusted fixture API, not a second native IPC run.

Fix: add an explicit consumer mutation-readiness preflight at new-command
admission, after duplicate receipt lookup and before INTENT or other new
command effects. A reopened/closed/uncertain file consumer must refuse new
activation without writing blobs, changing selection, or losing readiness of
the existing committed snapshot. Preserve lookup, `load_committed`, and exact
already-published-byte reconciliation. Do not clear the protected root's
read-only flag as a shortcut. Add direct-selector and authenticated broker
regressions for this restart case.
