Priority: P1 acceptance blocker. Contract: GT-02 invalid/full-journal rejection before apply; initial audit P-13; TX11 bounded durable journal/result semantics.

When the admitted PENDING consumes the last available record, terminal persistence is guaranteed to fail after the effect.

Executed an isolated real-socket diagnostic using the frozen modules, a temporary project and `JournalLimits(max_records=2)`. The lease consumes record 1; `fixture.set(value=37)` consumes record 2 with ACCEPTED_PENDING. Actual result:

The diagnostic Python host exited 0 after bounded lookup and context-manager cleanup. UNKNOWN is honest after this failure, but does not satisfy rejection before a predictable capacity failure. The existing full-journal test sets max_bytes=200 so admission itself fails; it does not exercise this frontier.

Required remedy: under the journal's serialized writer domain, account for the terminal record/byte obligation of every admitted pending command before accepting it, including competing commands and control receipts. Reject insufficient capacity before fixture mutation. Test both record and byte boundaries, concurrent pending obligations, reopen/compaction, and cancellation/Stop so a later admission cannot consume reserved capacity. ### A2 — Expired receipt is destroyed; required archive lookup is absent

Priority: P1 acceptance blocker. Original section 2.2 says expired commands are rejected and looked up in archive, never re-executed. This is an existing GT-02 contract, not an added GT-07 scheduler requirement.

Frozen `journal.lookup` at line 447 unconditionally raises RETRY_HORIZON_EXPIRED for an expired command. `compact` at line 496 replaces its status with EXPIRED_TOMBSTONE and receipt with `{}`. No archive storage or archive lookup exists. Transport lookup only calls that rejecting method. Preventing repeated execution is implemented; preserving a way to recover the old result is not.

Executed a second isolated diagnostic: append COMMITTED receipt at now_ms=0 with retry_horizon_ms=10; compact at 11; reopen; lookup at 11. The lookup raises RETRY_HORIZON_EXPIRED. The only retained command is EXPIRED_TOMBSTONE with `receipt:{}`; only journal.jsonl and its guard remain. Thus this is observable data loss for the required archive query, not merely an undocumented method name.

Required remedy: preserve bounded, durable archive data sufficient to return the original terminal result through explicit lookup while independently rejecting expired execution/retry. Cover compaction/restart, same-ID changed digest, archive quotas and corruption without reopening an old ID. Keep receipt bodies on disk rather than unbounded RAM.
