Run `GT02-S32-BOUNDARY-05` completed the fixed native matrix with actual parent
exit 0 and four native exits 47. Windows build 26200, Python 3.11.9, MSVC
14.44.35207 and SDK 10.0.26100.0 are recorded with executable/source hashes.
The C diagnostic compiled with `/W4 /WX`. No production capability was enabled.

The worker lane was interrupted at the owner's request after run03. The
coordinator resumed solo at its failed phase, preserved run01–04 and their

Both AppContainer primary tokens had the expected package SID, Low integrity
and zero capabilities. The restricted process queried NoChildProcessCreation=1.
Each native process reached its completion marker; final Job accounting was
active0 with an empty PID list. The restricted case's total process count was1;
ordinary cases include their fixed child/console helper accounting. The
inheritable sentinel's original bytes stayed unchanged.

One unique disposable profile was created through CreateAppContainerProfile
per run where needed, and deleted through DeleteAppContainerProfile. Run05
returned HRESULT0 for both, with package folder and SID registry mapping absent
before and after. Its owned TEMP was removed. This does not claim cleanup of
the separate S30 directory previously blocked by automatic approval review.
No existing account/service/ACL, global policy, network exemption or elevation
was changed; all file operations targeted synthetic owned fixtures.

Preserved failures and corrections:

- Run01: the native image inherited scratch Low integrity, so the ordinary
  control failed to create its result file (exit96). Run02 staged the executable
  in a separate RX directory without that Low label.
- Run02: native output was empty; JSON parsing obscured the startup result.
  Run03 captured partial/empty output explicitly and used unbuffered logging.
- Run03: ordinary/AppContainer matrices ran, but adding child restriction
  caused exit0xC0000142 before the restricted process marker.
- Run04: DETACHED_PROCESS replaced CREATE_NO_WINDOW, preserving the same
  console executable. The AppContainer reached native calls but an intentionally
  absent handle triggered STATUS_INVALID_HANDLE (0xC0000008), leaving partial
  JSON. The process exit and partial bytes are retained, not treated as PASS.
- Run05: only the deliberate handle-information probes catch that exact SEH
  status and record it as denial; all other exceptions propagate. With detached
  launch, the restricted process completed and refused child creation with
  ERROR_CHILD_PROCESS_BLOCKED (367). Other private/process access checks ran.

The evidence supports the measured launch combination. It does not isolate
every Windows startup internals cause. DETACHED_PROCESS and CREATE_NO_WINDOW
have distinct documented semantics; no GUI subsystem, alternate entry point,
console allocation or relaxed child restriction was used in the final run.
