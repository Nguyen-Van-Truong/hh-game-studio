## Decision and dependency boundary

GT05 is feasible with the installed pins, but neither current producer profile
nor the accepted GT03 import profile accepts the required asset fixture.
The shortest path is a small new pipeline profile with an original fixture,
reusing unchanged process/storage primitives where their contracts fit.

- GT03 is accepted. GT04 still requires the two independent final S60 reviews
  and coordinator acceptance. This report supplies neither signature.
- Section 8.1 permits separate schema/validator/fixture preparation after its
  data contract is locked. Pure naming/manifest/GLB test vectors may proceed in
  leased new paths; native export/import and integration remain behind GT04.
- GT04 must retain its declared support, no-I/O rejection of unsupported
  libraries/images, native save/reopen/material/context proof, Stop/deadline,
  actual exit/owned cleanup and same-closure evidence. A critic finding in
  these areas is a GT04 issue. Do not fix it by weakening an acceptance rule.
- Rig, clips, textures, asset naming/manifest, Khronos validation, Godot GLB
  import, visual parity and LOD are GT05 work. Their absence from GT04's closed
  box/material profile is documented; it is not a reason to add them to S60.
  TQ04's materialized-input rule applies when input intake is supported; the
  current profile rejects such intake before path inspection.
- Active cross-app activation, writable recovery and concurrency stay GT07.
  GT05 publishes only a verified staged snapshot. Real menu/input/play remains
  GT06; this fixture must not grow HH World gameplay or an asset economy.

## Exact contract points to settle before fixture code

The coordinator's new data profile and pure naming linter were inspected during
this review. Axis/tolerance/closed-intake choices match the plan. The coordinator
reports 12/12 focused tests; this lane did not rerun them. Static inspection of
`pipeline/naming.py` found no concrete defect in its declared naming-only scope:
closed fields, exact types, bounded lists, duplicates, class/role binding and
suffix headroom are checked, with no I/O or mutation. This remains preparation.

- Source: meters, Z-up, front -Y. Interchange: meters, Y-up, model front +Z,
  with `(x,y,z) -> (x,z,-y)`. Godot controller/camera forward is separate.
  Keep an asymmetric axis arrow and nose marker; a symmetric cube cannot
  prove front. glTF names are not inherently unique, so qualified manifest
  identities and fixture uniqueness are application requirements.
  [glTF units, axes and names](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units)
- Position: Euclidean error <=0.001 m. Bounds: componentwise absolute error
  <=0.001 m, with coordinate space declared. Scale: componentwise <=1e-4.
  Rotation: shortest quaternion geodesic angle <=0.1 degree, treating q/-q
  equally after unit/finite validation. Timing: <=1/30 s; define source frame
  endpoints and clip length explicitly. IDs, names, roles, counts/topology,
  licenses and source/artifact SHA are exact. A tolerance comparator must not
  turn into rounded-hash equality or erase a real edit.
- Proposed additional fixture tolerances (skin sum/material factor 1e-4) must
  stay recorded as profile choices, not attributed to TQ05's four defaults.
  Pin in-place root displacement, loop flags and empty events explicitly.
  Read clip sampling/poses, not only clip names or duration.
- Core GLB 2 only; embedded PNG uses `image.bufferView` plus `mimeType`, with
  no buffer/image URI or extensions anywhere. Bound compressed and decoded
  sizes before allocation, then actually decode in a capped worker. Check PNG
  dimensions/format, accessor stride/offset/count arithmetic, references,
  finite data, skin weights/joint indices and hierarchy cycles/depth.
- Use explicit `_lod0`, `_lod1`, `_collider`, `_nav` manifest roles. Pin
  `nodes/use_node_type_suffixes=false` and `nodes/use_name_suffixes=false` in
  the future import preset and verify against the installed Godot pin. Clips
  named exactly `idle`/`walk` avoid loop/cycle inference; set/read loop flags
  explicitly. Godot suffix rules also recognize underscores and some
  format-specific behavior survives general suffix disabling.
  [Godot suffix rules](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/node_type_customization.html)
- Core glTF does not provide this project's LOD/collider/nav/event contract.
  The fixed Godot consumer must read manifest roles and prove the resulting
  objects. A mesh named `_collider` is not evidence of collision behavior.
- The coordinator resolved suffix headroom during this review: asset IDs are
  capped at 55 characters, node names at 64, with an exact boundary fixture.
  The combined-GLB validator still needs to forbid ambiguous effective names
  or automatic `.001` repair; typed per-asset naming does not prove assembly.
- The coordinator reduced the draft intake ceiling to 1 MiB GLB/256 KiB JSON,
  and recorded 1 MiB per published blob. Keep source blend, manifest and total
  bundle capacity admission explicit too. Decoded textures can still reach
  128 MiB, so a bounded decoder remains required despite small compressed GLB.

## Minimal fixture and negative matrix

One original tiny scene can cover the required positive workload: axis cube
and arrows; an opaque PBR prop with small embedded base-color/normal/ORM test
textures; one rigged avatar and one outfit sharing the rig; body/outfit LOD0
and LOD1; idle/walk; one hand socket with visible attachment; separate collider
and nav proxy. Add a small material/alpha/culling diagnostic patch or explicit
unsupported cases so material policy is observable. The authored Godot wrapper
owns the script and external material override, references the imported scene,
and keeps gameplay code outside generated files. Godot documents that extracted
material overrides survive reimport, while renaming their source material
breaks the association; make that a migration fixture.
[Godot material reimport](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/advanced_import_settings.html)

Required focused negatives: malformed/truncated GLB and chunk/accessor bounds;
duplicate JSON keys; cyclic/overdeep hierarchy; URI/unknown extension;
oversized/corrupt PNG and decode bomb; NaN/Infinity; wrong axis/scale/winding;
zero/missing joint or invalid/non-normalized weights; unbaked IK/unsupported
shader/driver/GN/morph; missing/truncated clip; bad name or LOD rig/socket
reference; missing texture/source/license; actual bone rename/delete migration;
stale source/preset/tool hash; missing output, partial manifest, failed readback
and interrupted staged publication. Every failed candidate preserves last-good.

TQ05 budgets stay: avatar LOD0 <=8k triangles, LOD1 <=2k, <=60 bones and
<=2 materials; total decoded textures <=128 MiB; fixture scene <=300k triangles
and <=150 draw calls. Draw calls and appearance need Godot render evidence,
not inferred GLB metadata. Two export SHA values may differ; compare the full
numeric semantic records with the locked tolerances, then prove a real edit
changes the comparison result. Keep source closure, exact artifact identity
and semantic comparison as distinct records.
