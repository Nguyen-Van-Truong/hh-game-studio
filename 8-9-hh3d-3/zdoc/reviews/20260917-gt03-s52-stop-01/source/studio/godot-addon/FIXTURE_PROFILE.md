# Complete managed fixture eligibility and readback

This internal candidate does not advertise a runtime capability or issue a
public ACK. The installed frozen release supplies `fixture_profile.py` and
`fixture_profile/source-pins.json`; request content never selects release pins,
paths, executable arguments or plugins.

The eleven bundle files contain the scene, generated script, its retained UID,
fixed project config, three trusted addon scripts and their UIDs, and plugin
config. Nine immutable inputs are checked against exact installed source bytes.
Their role names in a caller manifest are not proof of trust. A scene UID may
not collide with any script UID in this complete fixture. `bundle_v2.py` remains
an inert byte codec; `fixture_profile.qualify` adds closed scene/script grammar
eligibility and exact release-byte checks without loading an engine.

The four script UID sidecars were generated by pinned Godot 4.7.2 and verified
by fresh native `ResourceLoader.get_resource_uid` readback. Reproduction and
hashes are preserved in `zdoc/reviews/20260917-gt03-s49-uid-bootstrap/run-02`.
Run-01 had no captured marker because the Windows GUI executable did not emit
stdout. Run-02 reused those exact IDs and used `--log-file`.

`validation_bootstrap.gd` is a separate pinned, read-only harness. After host
eligibility, the Linux `profile-validate` mode runs three fixed phases inside
one container and one PID1 wall deadline: check-only parse, editor import, then
the fixed harness with a fresh Script instance and PackedScene instance. Import
cache exists only in that container's capped `.godot` tmpfs. The candidate does
not provide the harness or a completion marker. The config/addon/UID files are
read-only and the generated script permits only typed literal declarations,
with no methods, static initialization, custom base, resource loads or hooks.
This finite profile is an explicit availability restriction, not support for
arbitrary GDScript, arbitrary TSCN or imported assets.

The harness observes exact script source/disk/UID hashes, reload return code,
native base and method/signal/constants lists, defaults, fresh instance values,
SceneState properties, node hierarchy/owner/stable IDs, local transforms and
unshared BoxMesh sizes. It frees detached instances before exit. No submitted
Node is added to a live editor or Play tree by this diagnostic.

`profile_readback.compare_observation` independently qualifies the bundle again
and compares all required fields. Script float values use exact binary64
roundtrips from `JSON.stringify(..., full_precision=true)`; binary32 vector
comparisons have a separate 2e-6 relative/absolute tolerance. A nonzero value
may never become zero. SceneState's `./Child` paths are compared separately
from instantiated Node paths such as `Child`. Neither shape is rewritten in
evidence. The pure comparator returns `process_attribution_proven=false`:
caller-supplied JSON alone cannot prove execution.

`run_profile_probe.py` freezes the complete source, supplies fixed trusted
inputs, then checks actual host/container exits, bounded streams, checked Job
close, source/snapshot/harness hashes, admission, exact phase/marker order and
owned removal before accepting a scoped observation. Old failed runs remain
unchanged. It still reports `sandbox_acceptance=false` and `public_ack=false`.
Full runtime boundary acceptance, authenticated command authority, v2 journal
selection, crash recovery and durable publication are separate remaining work.

Primary references: [Script.reload and reflection](https://docs.godotengine.org/en/stable/classes/class_script.html),
[SceneState](https://docs.godotengine.org/en/stable/classes/class_scenestate.html),
[ResourceUID](https://docs.godotengine.org/en/stable/classes/class_resourceuid.html).
Runtime evidence uses the exact 4.7.2 source pin; current documentation is
explanatory, not an alternative pin.
