# GT-06 O1.9 stock-editor control brief — 2026-09-29

`AUTHORITY=0`; this is a diagnostic plan/interpretation note, not acceptance.
Formal08 failed O1 on host private-commit growth/trend and editor handles, so
O1.9 permits a control. The control must use the same pinned Godot binary, copied
fixture, editor settings, one process/Job and host observation method, while
removing `hh_benchmark` and all HTTP/native mutation cycles. It must record
actual editor exit, Job/tree/handle cleanup, source hash and the same startup
window.

The existing S188 package is useful prior evidence: 720 seconds of editor-idle
with 2,685 retained handle samples, actual editor/driver exits 0 and clean Job,
showing non-monotonic handles (post-startup range 480–576). It used an older
source closure and does not substitute for a current-source control. S192's
comparison likewise says the control cannot prove a leak or subtract values
from formal.

A current control should therefore be run once, under a fresh diagnostic ID,
after no live campaign remains and after a new O4.1 preflight. Capture startup
plus the bounded idle window and editor counters; do not run the 35×100 command
mix, do not enable benchmark plugin, and do not change O1 thresholds/timeouts.
Compare shape and trend only. Never subtract control counts from formal values,
and never relabel a control PASS as GT06 acceptance.

Decision rule: if stock idle shows the same handle fluctuation, attribution to
the tool/plugin remains unproven and the formal failure stays a product FAIL;
if stock idle is stable, investigate the plugin's measured path with a bounded
source-level diagnostic. Either result is diagnostic and cannot unlock GT07.
