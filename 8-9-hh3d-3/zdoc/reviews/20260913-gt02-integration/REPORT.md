# GT-02 cross-module integration review

Date: 2026-09-13  
Test: `python -m unittest 8-9-hh3d-3/studio/tests/protocol/test_integration.py -v`  
Result: **6 tests passed**

The new tests exercise the shared wire profile together. `studio.protocol` is
the typed schema (`hh-studio-0.1`, mapping target, prefixed payload hash), and
`studio.host.core.limits` is its policy layer. Both reject unknown fields,
unsupported schema, over-depth values and malformed digests before dispatch.

## Expected compatibility policy

An adapter must negotiate exactly one schema/version before dispatch. Legacy
`studio.command.v1` string-target envelopes are rejected with
`UNSUPPORTED_SCHEMA`; there is no implicit field mapping or digest conversion.

## Findings

* The previous profile divergence was resolved by making the host validator
  consume `hh-studio-0.1`, mapping targets and `sha256:` payload hashes.
* The host parser now applies bounded depth/member/array/string limits and an
  exact field allow-list. Safe writes remain fail-closed without an OS handle
  primitive, and journal/lease persistence is separately tested.

These are compatibility findings, not hidden failures: the integration tests
assert the current permissive host behaviour so CI exposes the gap while
remaining green.  They should become rejection assertions once the host guard
is tightened.
