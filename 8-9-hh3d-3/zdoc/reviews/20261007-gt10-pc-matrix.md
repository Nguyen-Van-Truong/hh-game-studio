# GT-10-PC release slice — gated preparation

Status: `PREPARED_ONLY`, `AUTHORITY=0`, `GT-09_ACCEPTANCE_REQUIRED=1`.

This document prepares the PC-only release slice authorized by O12. It does
not open GT-10, accept GT-08B, or claim Android support. The full GT-10 remains
blocked until the owner supplies physical Android evidence or explicitly
reopens that target.

## Scope

Targets are Windows, Linux and Linux-headless. The package must carry
`android=DEFERRED_NO_DEVICE` and must fail closed if it contains Android
claims, payment/monetization code, or a failpoint-enabled build.

Required checks after GT-09 is accepted:

| ID | Scenario | Required observation | Result |
| --- | --- | --- | --- |
| PC-PKG-01 | Build package v0.1 from one frozen source closure | manifest, source hash, binary hashes, no `zdoc/reviews` or secrets | NOT RUN |
| PC-PKG-02 | Install into clean Windows fixture | actual installer exit, installed files and version readback | NOT RUN |
| PC-PKG-03 | Install into clean Linux/headless fixture | actual installer/launcher exit and dependency readback | NOT RUN |
| PC-PKG-04 | Upgrade old → new | old save/art preserved; schema migration and version readback | NOT RUN |
| PC-PKG-05 | Roll back new → old | compatibility floor, source/save integrity and actual exit | NOT RUN |
| PC-PKG-06 | Uninstall | addon/package removed without deleting game art/save | NOT RUN |
| PC-PKG-07 | Handoff | another clean consumer opens, plays and reads the manifest | NOT RUN |
| PC-PKG-08 | Release soak | 10 fresh pairs × 35 batches on the same frozen release source | NOT RUN |
| PC-PKG-09 | Negative package scan | Android claim, monetization, failpoint, secret and stale hash all reject | NOT RUN |

## Gate rules

1. Do not run any row until GT-09 is coordinator-accepted and the release
   source is frozen. A diagnostic pass, banner, or candidate critic package is
   insufficient.
2. Every row records run ID, command ID, seed where applicable, actual host
   and child exits, owned Job/tree cleanup, source/package hash and raw path.
3. Use fresh IDs after a source change. Preserve failed raw evidence; repair a
   proven boundary before retrying and never combine rows from different
   closures into one acceptance package.
4. Two independent read-only critics must review the same final PC package
   hash. The coordinator may accept only after both explicit `TICK=yes`.
5. A PC pass is a PC release result. It cannot be relabelled as Android or as
   full GT-10 acceptance.

## Deferred dependency

`GT-08B=DEFERRED_OWNER_NO_ANDROID`. No emulator substitutes a physical device.
When the owner later supplies an Android device, run the original GT-08B gate
with a new source closure and then produce a separate full-GT-10 manifest; do
not mutate this PC evidence.
