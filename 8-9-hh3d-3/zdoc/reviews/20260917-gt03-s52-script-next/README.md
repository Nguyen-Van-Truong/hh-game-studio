## Choice: one-time trusted generation seed

A host epoch/session tuple is explicit but would require catalog/context changes for every mutation, nested preview and pending request; omitting the tuple from even one path would leave an ABA hole. The smaller compatible choice is `EditorOwner(..., initial_generation=1)` and a fixed, authenticated, **one-time** `seed_generation` IPC before any effect. For replacement, its value is derived from the exact retired owner's final actual generation plus one. The caller cannot supply this value through a public operation. Plugin rejects non-integers, duplicate seed, seed after an IPC effect, dirty UndoRedo state and overflow. It rebinds the existing native root through `_bind_current`, so scene snapshots/SceneCommands continue using the same integer expected_generation protocol.

The proof binds old/new process creation time, session, project root identity and distinct source-owned registered receipts. Root object instance IDs may numerically coincide across different processes; require their enclosing editor identities, not inequality of those scoped numbers. Persist `next_generation` / old and new identities in journal v4. Any recovered writable owner must allocate a greater generation from verified durable custody; default seed=1 is only for a genuinely new project, never permission to resume an old journal. Contract/catalog revision still changes for the new operation/grant semantics, but the envelope/scene mutation wire needs no epoch field.

## Draft API and ordering

1. After exact Linux candidate validation/staging and a fresh auth/lease check, call `old.retire_for_replacement(command_id, digest, expected_snapshot=ready, deadline_ms=...)` under a registered retirement STARTED phase. `ready` must match the captured old root's revision/generation/root/state/all working bytes; the root separately verifies selected project/FileVersion. Overflow is checked before an editor effect. The fixed main-thread `retire` command replies with its last guarded snapshot, disables IPC effects, flushes that reply and quits. Host proves process exit 0 and checked Job zero/closed before issuing a registered `EditorRetirementReceipt`. This first route remains the existing fresh private headless fixture: it is not a general lock on an artist GUI project.
2. Retain the old owner/receipt. `retirement_observation` validates exact registered receipt values, artifact bytes and close proof even though the owner is now closed. A killed/missing-exit/tainted/uncertain close does not mint retirement proof and cannot launch a successor.
3. Root durably records retirement and performs its usual complete-bundle selector CAS/SELECTED. Never start the next editor before the old lifecycle is proved closed; never rename scene and script into the old live mirror.
4. Under the admitted adoption phase call `EditorOwner.open_selected_generation(old, retired, parent, selected_bundle, editor_binary=..., selection=..., semantic_bytes=...)`. This uses the **same** existing owner constructor, not a duplicated launcher. It checks the nine immutable/non-scene/script files, profile, exact proposed semantic hash, registered prior closure and derived seed. The method does not prove a selected descriptor or user grant: only the coordinator/journal may provide those after verified SELECTED.
5. The new owner reads its actual root snapshot plus attached GDScript metadata through `script_state`. That read calls no ResourceLoader reload/new/execute and no source setter. It verifies disk/source hashes, UID bytes, closed-profile class/method/tool constraints and every typed script default, then compares full live semantic JCS and all eleven input bytes. This catches a changed default even when the scene overrides it. The registered `EditorGenerationReceipt` has a distinct cross-process schema. `observation` revalidates current root/generation/files/script metadata and the predecessor's registered close proof every time.
6. Root retains both owner references until adoption is durably recorded, then switches its active editor. The final commit STARTED phase reobserves the new generation before READBACK/COMMITTED. Failures retain UNKNOWN/reconciliation; no automatic writable rearm or implicit replay. The old closed generation remains a checkpoint and cannot receive mutations.

## Integration work outside this draft

Journal v4 must record typed retirement plus `old_editor` / `new_editor` adoption; do not normalize the new PID into v3's same-editor fields. The coordinator must bind selected native FileVersion, source closure, proposed script hash, Linux receipt, fresh owner registration and auth phase. It must retain cleanup_owner on constructor or successor cleanup failure. A startup failure after SELECTED still leaves one complete selected bundle; do not claim the old editor remains active or automatically roll back the selector.

Apply both patches together only after the current freeze. Recompute plugin source-pins once, finish S53 source changes, then run one actual baseline remint. Leave S52 frozen source/evidence unchanged. No active core/protocol edits are proposed.
