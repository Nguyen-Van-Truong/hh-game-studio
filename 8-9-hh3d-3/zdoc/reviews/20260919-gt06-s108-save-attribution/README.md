# S108 save attribution diagnostic

One fresh owned campaign prefix runs original full-mode batches 0 through 6,
each with 1,000 HTTP commands and 100 native semantic cycles. Original source53,
profile, stock `EditorInterface.save_scene()`, native phase deadlines and screen
gates remain unchanged. The first original gate failure stops the prefix. When
all seven original gates pass, `S108_PREFIX_BOUNDARY` stops before batch 7 work.
This package never creates a formal dataset, retries, or claims acceptance.

The exact S106 `956a1c56...` ownership utility and original campaign provide
import, editor, producer, Stop, Job and probe lifecycle. Diagnostic helpers and
generated overlay are frozen outside `studio` to keep the original imported
source closure at 53 files. Context binds run/index/attempt, original source and
profile, executable hashes, helper bytes, generated bytes and diagnostic closure.
Every run ID is exclusive. `.gitattributes` preserves exact helper bytes.

At READY 0 the startup marker binds the owned editor HWND and original binary;
the sampler independently resolves the Windows thread and retains its query
handle before the warmup baseline. No observer thread is created. CPU sampling
uses existing NativeLog polling only after successful START publication and
through BATCH return for native batches 5 and 6, at approximately 50 ms with an
8,000-record cap. HTTP intervals do not sample. Initial CPU accounting read at
thread attachment establishes identity but is not a measurement series.

Each original ACK publication is bracketed by a timestamp before the original
publish call and one after its native receipt returns. Native ACK times and exact
receipts are retained without changing the payload or deadline. These conservative
clock bounds support `clock_join.py` only after raw evidence is persisted. The
first save may lack an enclosing sample because sampling begins after successful
START publication; that interval must remain UNKNOWN. CPU envelopes do not prove
a wait cause, exact per-call CPU, starvation, disk blocking, or a root cause.

All attribution records stay in bounded memory during work and are written to
`attribution-raw.json` after the original campaign cleanup. Original gate exceptions
win over sampler, close, or evidence-writer errors. Separate terminal console
receipts preserve primary/finalization error codes if raw writing fails. The added
thread handle receives a checked native close receipt. Other lifecycle records
distinguish actual target exits from helper exits, checked Job/probe releases from
the unavailable original import wrapper native CloseHandle BOOL, and the outer
runner exit that only an external passive observer can record.

The parent checks a valid bound Stop before dispatch and on each owned wait tick;
the owned wait has a 1,200-second outer deadline. Host timeout/Stop can terminate
the child before its finally dump, so missing data stays incomplete. No PSS,
post-idle sampling, overhead subtraction, cache walk, or gate relaxation is used.
The capture manifest uses bounded evidence slots and excludes private caches,
temporary directories and command journals.
