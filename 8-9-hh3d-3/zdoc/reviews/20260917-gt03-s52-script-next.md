# Next GT-03 slice: bounded script_text.replace

AUTHORITY=0. Implementation design only; no runtime source edits, native engine run or critic acceptance. Read against the S52 working sources and plan sections 2.3 / GT-03.

**Recommended route:** keep the exact declarative script profile and reuse complete-bundle publication. For a script replacement, adopt a freshly launched owned editor generation from all eleven selected files. Do not extend the current scene-only adoption RPC to rename the scene and script separately inside one live project. Two renames plus ResourceLoader cache handling would add a second publication mechanism and a partial-generation window. A short editor restart/history boundary is appropriate for this managed fixture and also advances GT-03 recovery work.

## Existing pieces to reuse

- `contract.py:validate_request` already validates fixed path `scripts/fixture_actor.gd`, expected semantic/project revision, generation, expected script SHA256, bounded full UTF-8 text and a proposed preview. `scene.preview` already supports nested `script_text.replace`. Its current preview gives hashes/counts, not the actual changed lines.
- `script_profile.py:validate_script` accepts only ASCII declarative `extends Node3D` plus ordered typed literal exports: required fixture_value, optional move_speed/turn_speed/enabled, within existing bounds. No methods, expressions, initializers with calls, inheritance paths, @tool, preload/load, signals or arbitrary imports are accepted. Preserve this boundary and the 16 KiB cap.
- `EditorOwner.prepare_effect/capture/capture_bytes/captured_semantic` obtains the real dirty scene without rewriting the working mirror. `factory.compose(captured_scene, proposed_script, ...)` makes one complete eleven-file candidate; `factory.qualify` rejects an unsupported script/scene before Godot starts.
- `ValidationOwner.validate → bind_semantics → semantic_observation` already performs actual isolated Linux parse/import/fresh-instance checks and binds the full observed semantic revision. `ProtectedBundleStore` already stages twelve native objects (eleven inputs plus manifest) and selects the whole descriptor with one native CAS.
- Current v3 journal supports only scene.save. Its CAPTURED/PREPARED rules require unchanged non-scene inputs and final semantic revision equal to the old editor revision. Those rules must not simply be deleted to admit scripts. `EditorOwner.adopt` intentionally rejects a non-scene change; keep that existing route intact for scene.save.

## Smallest complete command flow

1. Add typed grants/runtime routing for `scene.preview` and `script_text.replace`. Preview uses a read lease, current root/revision/project/script hash and bounded unified text diff (for example 256 lines / 32 KiB, with explicit truncation plus exact before/after hashes); no file or engine effect. Full replacement, not a new patch language, satisfies the plan's patch/full-text choice. Bind the applied operation to the same exact request/preview digest. No preview data becomes a validation receipt.
2. Extend the write lease/phase admission API to bind the actual operation. `PublicationSession` currently hardcodes scene.save in `lease/check`; a script-only grant must not gain scene.save authority or require it implicitly. Keep separate capture/stage/select/adopt/commit STARTED accounting, Stop/revoke behavior and effect deadlines.
3. Validate the proposed text with the closed profile before capture. Durably record operation, old selected checkpoint, old scene/script hashes, proposed script hash and byte count, original editor identity/generation/root and request digest. The hash-bound request text is the byte source; caller metadata alone never supplies a final bundle.
4. Capture the actual dirty scene through the existing registered owner. Build the candidate using those exact scene bytes and the proposed script bytes, with the other nine inputs byte-identical. Run existing isolated validation, then bind its new full semantic revision. Unlike scene.save, this revision is expected to differ from the old captured semantic state. Validate scene structure/transforms/metadata and exact scene bytes against capture; compare new script defaults/instance semantics to the proposed script using the existing comparator. The full new semantic snapshot is authoritative only after actual validation and live editor readback.
5. Persist PREPARED/STAGED/VALIDATED, then recheck grant/lease, old selected native version, old editor generation/root/revision/files and exact candidate receipts. A schema revision (v4) should record both original capture facts and the distinct final candidate facts. Preserve a single project journal, selector and command ID; never make independent scene/script journals. New reducer rules allow only the declared script delta plus captured scene, preserve nine other inputs, and bind final semantic revision to the registered candidate validation.
6. For script replacement, perform a declared editor restart boundary: final old-editor guard, stop/close the old owned editor and verify its Job drain; retain its checkpoint and closing identity. Then CAS the complete selected descriptor and persist SELECTED. Launch a fresh owned editor from the exact selected eleven files, verify actual PID/creation/root identity and fresh script disk/source hashes, compare the complete live semantic bytes to Linux validation, and only then register adoption. No partially rewritten live mirror exists. This uses different project directories/process identities; it is same-application generation replacement, not cross-app activation.
7. Persist the old→new editor identity relation and generation transition. The new process's local generation starts at one today; add a strictly validated host-controlled generation base (or explicit journal-owned editor epoch) so old-generation commands cannot become valid after restart. Do not fabricate same-session adoption or reuse the old root ID. Registered fresh-owner readback must recheck all eleven current file bytes and actual root/generation, with an explicitly empty/new UndoRedo history.
8. Keep final adoption observation + READBACK + COMMITTED inside the admitted final commit phase. Any crash/uncertain close/CAS/startup becomes UNKNOWN and read-only reconciliation. Reopen must inspect the selected complete bundle and durable phase, and must not resurrect an old editor/session/lease automatically. Enable a fresh writable recovered owner only with separate proven custody/recovery authority. A successful restart from known selected bytes is not permission to call private store rearm APIs.

## Required changed files / APIs

- `operations.json`, `contract.py`: runtime-supported profile and restart/history policy, real bounded preview; retain strict request schema and old script hash.
- `publication_session.py`, `publication_owner.py`: operation-bound write authority, shared publish helper with explicit scene-save vs script-replace branches, deterministic early rejection and final commit accounting.
- `publication_state_v3.py` / `publication_journal_v3.py`: use a new explicit schema version for the expanded command/adoption facts, or successors if preserving v3 replay compatibility requires it. Avoid another unrelated journal implementation. Typed `capture_prepared(operation, proposed_script_metadata, ...)` and new adoption binding must validate exact changed-file policy.
- `editor_owner.py`, `plugin.gd`: registered fresh-editor adoption facts and host-owned generation seed; retain the existing same-session scene-only adoption method. No live script source overwrite API is needed for the restart route.
- Existing `bundle_v2`, `protected_bundle`, `script_profile`, `scene_profile`, Linux executor and validator should need no policy broadening. Changes to them need a concrete missing invariant, not duplication.

## Verification before advertising capability

Focused pure/native cases: successful script default change (including a scene override masking that default); dirty scene plus script change in one selected project revision; bounded preview and unchanged-before-apply; stale script/revision/generation/lease; invalid UTF-8/oversize/@tool/executable source rejected before Windows editor; actual sandbox parse/import failure never reaches activation; Stop/revoke before/during each new restart/commit cut; no mixed selector after scene+script crash cuts; response loss replays the exact durable result; old process drained and old-generation commands rejected; fresh editor script source hash and full semantic equality; failed startup leaves UNKNOWN with a complete selected generation. Parser-denial unit injection is useful but must be labeled as injected, not a genuine engine syntax-failure observation.

An invalid script rejected before any capture/publish effect can be REJECTED. A clean isolated parse/import failure before selection can durably become FAILED with the old selected generation unchanged. Do not collapse every deterministic validation failure into a successful save, nor silently restart a held validator. Cleanup of that attempt must be proved before creating another validator owner.

**Scope limit:** this completes a closed declarative fixture operation, not general GDScript editing, arbitrary @tool/import support, or permission to execute new gameplay code in an unsandboxed editor/Play. Keep unsupported general source explicitly disabled. GT-03's broader verification and recovery/critics remain required; this report does not waive them.

## API research informing the choice

Godot documents that setting Script.source_code does not automatically reload the implementation, and Script.reload is a separate operation: [Script](https://docs.godotengine.org/en/stable/classes/class_script.html#class-script-method-reload). Cache replacement has distinct resource/dependency behavior: [ResourceLoader](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html#enum-resourceloader-cachemode). Scene reload is another editor operation: [EditorInterface](https://docs.godotengine.org/en/stable/classes/class_editorinterface.html#class-editorinterface-method-reload-scene-from-path). Choosing a fresh complete generation is an engineering inference that avoids relying on these APIs to provide atomic scene+script publication; the chosen behavior still needs proof on the pinned 4.7.2 binary.
