## Capability and claim audit

No falsely enabled public Godot capability was found in the inspected implementation. All nine `implemented`/`runtime_enabled` flags remain false (`studio/godot-addon/operations.json:33`); discovery defaults empty (`contract.py:138`). `plugin.gd:73` routes only fixed scene mutations/history and rejects save/script operations. Successful scene callbacks return `SCENE_APPLIED_IN_MEMORY` (`scene_commands.gd:351`), not `COMMITTED`. README/CONTRACT/BUNDLE and capture explicitly preserve the relevant limitations.

Two integration hazards must remain closed:

- Do not expose `apply_projection()` directly to a remote client. It receives a reduced projection without project/auth/lease/deadline authority; the missing host must authenticate, journal/checkpoint and recheck authority before effects. Local deduplication is bounded to 256 session receipts (`scene_commands.gd:11`, `:100`), not durable retry/Stop/lost-response handling.
- A fixed script path is not source trust. `scene_commands.gd:515` observes a GDScript at the allowlisted path and hashes its source; it does not establish that newly supplied content is approved before Godot opens it. The current fixture is trusted. Never route submitted source through the ordinary diagnostic editor launcher or treat the bundle codec as a parser/sandbox.

The separate `zdoc/reviews/20260916-gt03-s47-sandbox/HANDOFF.md` correctly reports startup in a zero-capability AppContainer, expected engine exit 87 and owned teardown. It also preserves two volume-query engine errors and explicitly lacks a hard disk bound, exercised network denials, child-launch denial attempts and hostile-script validation. `DISK-CAP-DECISION.md` is a proposed provisioned-storage contract, not implemented protection. This startup result must not be called a clean parser-sandbox pass.
