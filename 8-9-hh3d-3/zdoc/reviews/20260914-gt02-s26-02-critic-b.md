## Reproducible blocking findings

### B-01 — admission does not reserve terminal journal capacity

Relevant frozen code: `host/core/journal.py`, `Journal.append_command` / `_append` / `finish_command`; `host/core/transport.py`, `_submit` / `_execute` / `_finish`.

With `JournalLimits(max_records=2)`, obtaining the fixture lease writes record 1. Submitting `fixture.set(value=37)` writes the pending intent as record 2 and returns `ACCEPTED_PENDING`. The worker applies the effect, then terminal persistence fails at the record limit. Independent observation:

```json
{"admitted":"ACCEPTED_PENDING","terminal":"UNKNOWN","code":"RECOVERY_REQUIRED","fixture":{"value":37,"revision":"rev-1","effect_count":1},"journal_records":2}
```

The host correctly avoids a false COMMITTED response, but it applies work whose inability to retain a terminal result is predictable at admission. The existing journal-full transport test tests an empty journal with a 200-byte limit and an inspect request; it does not exercise the lease + pending + terminal boundary for mutation. This fails the P-13 admission/no-effect requirement and GT-02 journal-full verification. Reserve sufficient bounded terminal capacity before admission and verify both record and byte boundaries with actual mutating fixture work.

### B-02 — compaction destroys expired results without archive lookup

Relevant frozen code: `host/core/journal.py`, `lookup` and `compact`.

Append a committed receipt at `now_ms=100` with `retry_horizon_ms=5`, then compact at 106. Compaction changes the record to `EXPIRED_TOMBSTONE` and replaces the receipt with `{}`. `lookup` returns `RETRY_HORIZON_EXPIRED`; no archive lookup API or retained original result exists. Independent observation:

```json
{"code":"RETRY_HORIZON_EXPIRED","original_receipt_present_after_compaction":false,"archive_lookup_api":false}
```

The tombstone correctly prevents re-execution, but section 2.2 explicitly requires rejecting expired retries and looking up the archive. The original result becomes irrecoverable. This fails the archive portion of P-12/section 2.2. Preserve bounded on-disk result retrieval across compaction and expose a typed lookup path without making expired IDs executable.

### B-03 — credential rotation drops protection against secret identifiers

Relevant frozen code: `host/core/transport.py`, `SessionAuthority._mint`, `rotate`, `validate_public_identifier`, and `_submit`.

Issue a local credential, rotate it, and authenticate with the replacement credential. Submit a read command with identifier `"cmd." + old.bearer`. The request returns `ACCEPTED_PENDING`, and the obsolete bearer is persisted verbatim in the journal. No real credential was used or printed in this diagnostic.

```json
{"status":"ACCEPTED_PENDING","old_bearer_persisted":true}
```

`validate_public_identifier` checks redactors for current sessions only. Rotation replaces the session entry and its redactor, so the existing live-credential test misses the obsolete credential. Rotation successfully invalidates authentication; this finding concerns the separate no-secret-in-retained-output contract, P-18. Keep secret identifier admission fail-closed across rotation/revocation/expiry while retaining bounded memory and preserving exact public command identity.

from studio.host.core.journal import Journal, JournalLimits, JournalError
from studio.host.core.transport import LoopbackFixtureHost, FixtureClient

scopes = frozenset({"fixture.read", "fixture.write", "control.stop", "control.cancel"})
with tempfile.TemporaryDirectory(prefix="gt02-critic-b-") as temporary:

    with LoopbackFixtureHost("project.fixture", root, journal) as host:
        credential = host.sessions.issue(scopes=scopes)

        assert client.submit(request).status is Status.ACCEPTED_PENDING

        assert result.code == "RECOVERY_REQUIRED"
