## TX15 safe-write GAP is retained, not waived

Section 2.2 expressly requires UNSUPPORTED_SAFE_OPEN_WINDOWS when the needed
safe primitive cannot be supplied, with consumer mutation disabled. GT-02's
BUILD scope is a path resolver and typed mock operation fixture. The current
implementation satisfies that explicit failure branch. `safe_open.py:154`
reports safe_open=false, safe_write=false and atomic_replace=false; its
root-probed object advertises only read_identity, and every mutator rejects
before file I/O. Windows handle/junction/hardlink tests support that limited
statement. The hardlink counterexample is a reason to keep write disabled.

TX15 also explicitly calls unavailable safe-open a GAP. That positive
safe-writer capability is still unavailable and must remain an open
requirement in capability/coverage and downstream gate records. This PASS
does not redefine GAP as successful safe writing, approve a general file
mutation path, or excuse a GT-03/04 spike from the same first-mutation safety
requirements. Any consuming adapter must first prove its private OS namespace,
handle/link/identity and publish protection and enable only that proven
capability. Until then, a requested file mutation remains unsupported. Linux
also remains unsupported. No Windows probe/design report is used here as
write proof, and this recommendation does not accept GT-03 or GT-04.

This interpretation uses the plan's existing explicit unavailable-capability
branch; it does not remove or move the positive TX15 requirement. An
unqualified claim that safe file mutation or all positive TX15 scenarios
are complete would contradict both this report and the candidate metadata.
