## Independent observed behavior

`Journal._load` (`journal.py:274`) now validates the complete history and performs
`flush`/`fsync` through an `r+b` handle before a guarded public method returns
records. The constructor and every guarded reload use the same barrier. This
prevents an object-local poison flag from being the only protection. Parsing a
partial terminal line fails before receipt exposure. `transport.py:507` maps the
tested unreadable/durability/integrity failures to UNKNOWN, closes work admission
and preserves the safe command ID without a `no_effect` claim.

The independent script constructs its own temporary root and real authenticated
loopback fixture. It durably admits PENDING, waits for exactly one fixture effect,
then injects a terminal persistence fault. Successful pre-terminal barriers are
allowed in the terminal-specific cases. After the selected failure, later fsync
barriers remain failed. The partial-write case writes half of the actual terminal
line, flushes it, then raises; the flush case makes a complete line readable and
raises before terminal fsync. These are deterministic I/O fault models, not an
experiment that damages storage.

## Coverage findings before freeze

The following are missing regression coverage or evidence boundaries, not
reproduced source defects:

1. The currently observed repository durability tests inject fsync failures.
   They do not retain the independent matrix's terminal write-before,
   partial-write and flush-after-full cases as candidate-suite regressions.
   Those cases passed this private diagnostic, but should be promoted into the
   frozen regression source so a later implementation cannot silently drop the
   protection requested in the earlier corrective review.
2. The current new repository tests reopen a Journal in the same interpreter.
   The independent matrix additionally starts fresh interpreters with their own
   fault injection and verifies archive after compaction. Retain this separate
   process test in the frozen coverage if claiming recovery independent of
   process memory; this preaudit alone is not a candidate manifest entry.
3. The exercised compaction failure is its initial recovery barrier. It does not
   inject temp-file write/fsync, replacement, or post-replace reload failures.
   No conclusion about all compaction crash phases follows from this matrix.
4. Real disk-full, device failure, power loss and OS reboot were not induced.
   These fault models prove bounded logic at the Python I/O boundaries. They do
   not certify power-loss durability of filesystem directory entries, storage
   firmware, engine state or future multi-file publish recovery.
