# GT-04 S56 — bounded next-step integration map

Design only, 2026-09-17 Asia/Saigon. Written outside `studio/` while the current
source is frozen for native runs. No engine, Registry, journal or production
mutation was performed for this map. It does not open GT-05/GT-07 or establish
acceptance. The current writer owner connects inspect and five transient edit
operations; save/checkpoint/export and native preview remain disconnected.

## Recommended implementation order

1. Add bounded native preflight/semantic preview and actual before/after diff
   for the existing edit profile. Keep it an observation, not another admission
   or publication mechanism.
2. Connect only `export.publish` through the existing `BlenderPublicationOwner`,
   after completing its deadline and Stop plumbing. It already matches the
   private publication request understood by `client_ledger.make_intent`.
3. Add fixed save/checkpoint profiles to that same publication owner and reducer.
   Keep these capabilities absent until their exact profile, reopen readback and
   protected selection path are tested. Merely exposing `UIAdapter._save` does
   not satisfy protected-save semantics or TX15.

This order avoids rewriting the tested protected owner while also keeping the
existing artifact publication phases as the single publication state machine.

The focused file surface is `blender-addon/adapter.py`, `ui_adapter.py` and
`ipc_client.py` for shared native preflight; `host/blender/ui_host.py`,
`client_transport.py`, `client_writer_owner.py` and `client_write_catalog.py`
for its bounded route; then `publication_owner.py`, `publication_state.py` and
`export_job.py` for file profiles/deadlines. Change `client_ledger.py` only where
the declared native profile binding actually changes. Do not alter core Journal,
HTTP framing, protected-file/custody primitives or the accepted Godot adapter.

## Native preview and diff

The smallest useful preview is a **native precondition check plus a bounded
semantic change list**, followed by an actual observed diff after apply. It is
not a claim that a predicted full Blender snapshot has already run.

- Factor the existing read-only validation from `blender-addon/adapter.py`
  `execute` and `ui_adapter.py` `_dispatch_checked`/`_history_step` into shared
  preflight helpers used by both preview and apply. Reuse `contract.validate`,
  object/material capacity checks, stable IDs, revision/context checks and the
  existing material profile; do not copy a second validator into the host.
- Run preview on Blender's main thread through a strict private IPC `preview`
  request and a corresponding `BlenderUIHost.preview` helper. A bounded native
  handler can inspect the at-most-16-object profile synchronously after control
  polling. It must check Stop, lease and original deadline before inspection
  and before returning. No operator, mode toggle, Undo push, save or export is
  permitted. It must not occupy the apply command's queue receipt/ID.
- An explicit host `/v1/preview` route can accept the same common Request for
  validation/translation, without changing its schema or recording a common
  mutation INTENT. Authenticate the operation, resolve the current writer
  lease, take the existing bounded work slot, check exact owner/source and
  expose only preview observations. It does not consume an effect permit,
  reserve the apply ID or authorize a later mutation. Actual submit repeats
  every authority/revision/context check; preview is not a reusable grant.
- Return the observed native revision/context, public request digest, private
  command digest, source/generation, stable target IDs, requested field changes,
  affected files and Undo/recovery policy. Create/transform/material previews
  distinguish requested values from existing binary32 readback rules. Do not
  invent an `after_revision`. Undo/redo may show the already-observed target
  snapshot from owned history only after exact current-history checks.
- After a real edit, calculate a capped semantic diff from the existing native
  `before`/`after` observations and include it in the common terminal response.
  Keep native revision hashes opaque and the public diff/observation hash in
  the named JCS domain. Reject over-cap output; do not silently truncate it.

This supplies the declared dry-run/diff/affected-file/Undo policy in §2.6 for a
limited supported profile. If acceptance requires execution of a proposed edit
in a separate native clone, that remains an explicit additional gap; a semantic
preview must not be relabeled as such a simulation. Inspect and Stop must not
acquire a preview prerequisite. Destructive edits remain gated on a proven
checkpoint; do not expand the existing operation set to delete/rename here.

## Connect file operations through the protected owner

| Public operation | Existing useful path | Smallest missing integration |
| --- | --- | --- |
| `export.publish` | `client_write_catalog.translate` → publication request; `BlenderPublicationOwner.publish` → `export.prepare` → `ExportJob.run` → protected bundle/manifest/selector; `read_selected` verifies it | Bind the exact publication owner to the writer owner, thread deadline/Stop through all phases, validate the internal result and selected bytes, then persist the common terminal response. |
| `scene.save` | Translation currently produces `checkpoint.save` with native fixed slot `fixture`; `_save` reads back unchanged scene/context and creates `fixture.blend` | Add a server-selected scene-save profile to the existing publisher. Protect the resulting blend, manifest and selector with existing primitives and perform fresh native reopen verification. A native slot file alone is not the protected artifact. |
| `checkpoint.save` | Same native path with fixed slot `checkpoint`; existing recovery owner can reopen a selected export bundle read-only | Add a server-selected checkpoint profile to the same publisher and verify its selected blend. Do not claim prior Undo history, arbitrary file intake or writable recovery. |

The publisher is currently **one bundle per storage owner**, hardcodes
`checkpoint.blend` plus `scene.glb`, and validates an Object-mode, nonempty,
box/material export profile. `ExportJob` also hardcodes `export.blend` as input.
These are real constraints, not configuration already available to save calls.

For saves, extend only the existing publisher/reducer with a small closed profile
enum that pins the native preparation slot, protected artifact names, validator
and affected-file list. Persist that profile in the publication binding/history
and preserve the current export profile's exact read-only history validation.
Reuse CONFIG → INTENT → STAGED → SELECTING → TERMINAL and its STOP handling;
do not create a separate save journal or a second reducer. Any schema evolution
needs old-export-history rejection/compatibility tests before it is advertised.

The first supported save profile can remain Object-mode boxes/materials and
reuse the existing background reopen/export validation worker, explicitly
declaring any temporary GLB verification output. This is narrower and more
maintainable than introducing another unrestricted `.blend` loader. Supporting
empty scenes, Edit Mode or a blend-only worker is a separate explicit profile
gap. Native fixed slots currently refuse overwrite; declare the bounded
one-save-per-slot/owned-session limitation until a checked replacement design
exists. Do not silently turn repeated save into arbitrary overwrite.

## Public identity, proof and response ordering

Keep responsibilities separated by existing components:

- `client_ledger.py`: reserve `(project_id, command_id)` across sessions; bind
  the exact native request; issue one admission permit; retain exact common
  terminal bytes. Other sessions cannot reuse the ID or read its receipt.
- `writer_journal.py` / `client_writer_session.py`: current native writer fence,
  session authorization and the one-use effect transition.
- `publication_owner.py` / `publication_state.py`: artifact custody, stages,
  protected selection and internal publication result.

Do not route new public mutations through `DurableBlenderSession.execute_bytes`
in addition to the common ledger: that would add a second command receipt store.
Use the durable session for lease/Stop support and the existing publisher for
artifact effects. A bounded owner map retains the exact publisher/cleanup owner;
no new orchestrator state machine is needed.

Persist the common INTENT before publication effects. Bind the internal
publication request/profile and private command ID to that admitted intent.
On internal completion, verify `lookup_bytes` binding and `read_selected`'s
manifest, source/generation, protected versions, hashes and barriers before
constructing the public terminal observation. Bind opaque publication identity
and manifest/selector/artifact digests into that observation without exposing
host paths or secrets. Native revision text and JCS observation hashes remain
distinct domains.

Persist exact common terminal bytes once, then use the existing final delivery
gate. Retain `public_ack=false` and distinguish verified protected artifacts
from a running unsaved GUI, writable recovery and product acceptance. A lost
reply after common commit replays its original bytes. An internal publication
commit followed by uncertain common finish stays UNKNOWN/held: lookup may
inspect existing evidence, but must not rerun export or infer a new ACK.
Reopening a writable GUI or automatically reconciling cross-process commands
belongs to GT-07, not this bridge.

## Deadline and Stop plumbing required before connection

`PublicationOwner.publish/_native` and `ExportJob` currently do not carry the
new public absolute command deadline. The lease expiry and fixed 20-second
export watchdog do not substitute for it.

1. Add a strict trusted deadline argument to the publication bridge, preserve
   the originally admitted epoch deadline, and carry the original monotonic
   budget through the host phases. Derive each local budget from the minimum
   of that budget, request deadline, lease expiry, owner lifetime and existing
   stage cap. Clock rollback must not renew the original budget. Historical
   lookup/replay must continue before fresh-expiry checks.
2. Forward `deadline_ms` and remaining bounded TTL to every native prepare and
   post-export inspection. Check immediately before each fresh effect. Do not
   rely on `BlenderUIHost.execute`'s polling timeout as native authority.
3. Let `ExportJob` accept the caller's bound and use the shorter deadline before
   launch, before releasing its stdin gate, throughout polling, and before
   declaring validated output. Expiry/Stop drains or terminates only its exact
   owned process tree and retains real native/wrapper exits and cleanup state.
4. Check authority/deadline before protected artifact creation, STAGED, SELECTING
   and selector activation. Once selector replacement may have happened, a
   later timeout cannot become a no-effect rejection; retain actual evidence
   and classify uncertainty. Public grant ordering and source/lease checks must
   not hold a session mutex across filesystem or journal waits.
5. Route public Stop to the exact active `PublicationOwner.stop`. Its ExportJob
   lives in `publication_owner._job`, **not** `ui_host._export_job`, so the current
   writer → durable → host Stop chain alone misses that background job. Preserve
   the publisher's early stop flag/job cancellation before its long mutex, the
   dedicated transport Stop listener and the exact cleanup owner.

These are plumbing changes to existing owners, not a new deadline service or
job framework. Common Request and accepted core GT-02 primitives remain intact.

## Minimum proof before advertising each capability

Focused inert tests should cover preview/apply validator parity, no consumed
apply ID, project-wide dedupe, caller/source/lease binding, clock advance and
rollback, each deadline boundary, Stop/revoke ordering, exact common terminal
loss, artifact/profile mismatch and unchanged committed bytes under redaction.

Native proof must separately show:

- Preview leaves scene/context/Undo history and files unchanged in every
  advertised mode; actual diff matches real readback after create/transform/
  material/owned history; stale/manual changes between preview and apply reject.
- Each file profile produces its claimed artifacts, fresh background reopen
  matches native snapshot/context/profile, protected selector/barriers read back,
  and common Request → native intent → publication result → Response is bound.
- Expiry before prepare, during background work and before selection causes no
  late activation; selector/terminal interruption is UNKNOWN or an exact existing
  result, never an invented rollback. Stop drains the actual export Job.
- Response loss and duplicate/foreign-session retry produce no second file or
  scene effect. Partial files, disk-full/locked target, missing dependencies,
  link/alias swap and safe-open unavailability fail closed with explicit gaps.

Use existing export/publication/recovery test drivers and primitive fault hooks
where possible: `tests/blender/test_publication.py`, `test_export_cleanup.py`,
`test_client_writer_owner.py`, `test_client_ledger.py`,
`run_publication_probe.py`, `run_publication_recovery_probe.py`,
`run_export_cleanup_probe.py` and `run_checkpoint_recovery_probe.py`.
TX15 still requires handle-pinned identity/hash/custody and
barrier checks, not a `Path.resolve` or rename-only substitute. Every native
package needs one stable source closure, actual child/wrapper exits and owned
Job cleanup. No Godot import pipeline or broad writable recovery is implied.
