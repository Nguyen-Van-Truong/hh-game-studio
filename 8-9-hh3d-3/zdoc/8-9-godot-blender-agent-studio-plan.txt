## 3. TÁM HẠNG MỤC BẢO TRÌ ĐÃ ĐÓNG

| Hạng mục | Kết quả đã làm | Kiểm nhanh |
|---|---|---|
| Settings | merge `project.godot` theo tập khóa yêu cầu, giữ section/entry không liên quan, đọc lại và rollback khi lỗi | `test_project_config`, `selftest config` |
| Blender clips/selection | giữ nhiều Action trên cùng armature; activate trước khi chọn; chỉ kiểm owners được xuất | `test_blender_recipe`, `selftest clips` |
| Observe | hỗ trợ `.`, root-name prefix, property có `/`, native const bool; không gọi method script tùy ý | `test_play`, `selftest observe/replay` |
| Bot | `--out`, `--plane auto|xy|xz|yz`; auto Vector2→XY, Vector3→XZ; fail nếu Play/position không có | `test_bot_hardening`, `selftest save_bot` |
| Save | ghi temp và đọc lại trước replace; giữ `.bak` hợp lệ; fallback khi primary hỏng/thiếu; không fallback âm thầm với version mới | `selftest save_bot`, W9 |
| Visual | project AABB của VisualInstance3D, mask camera và mesh phẳng/dốc/behind-camera; trả basis rõ ràng | W5 visual |
| Receipt | `--out` receipt ngoài project; chặn symlink/junction, collision và đường unsafe trước tạo asset và trước ghi | `test_blender_recipe`, W8 |
| Run/path isolation | profile user riêng cho từng Play, kiểm user_data_dir trước load; scene tạo nested dirs; junction kiểm tra bằng `lstat` trước resolve | `selftest replay`, path/transaction/export units |

Các thay đổi trên không sửa pin Godot/Blender, schema command, journal,
UndoRedo, lease hay đường cài package. Không thêm asset/reference có bản quyền.

## 4. HỢP ĐỒNG NGẮN PHẢI GIỮ

1. Một writer và một engine cho mỗi project path; command có `command_id`, retry
   idempotent/dedup và ACK chỉ sau readback từ process thật.
2. Mọi ghi dùng temp + atomic replace, checkpoint trước destructive change;
   path dưới allowlist, từ chối symlink/junction kể cả dangling junction.
3. Godot object chỉ trên main thread; editor và Play là process riêng; Stop/Pause
   ưu tiên và không làm mất ACK. Không để token/secret trong log/evidence.
4. Input trace có seed và 60 Hz; trace hash chỉ được claim khi Play thành công,
   có frame và user-data path đã được xác nhận. Mỗi run có run_id/source hash.
5. Code GDScript strict phải explicit type và không bỏ qua return value nếu kết
   quả ảnh hưởng tới postcondition. Không coi PASS banner, ảnh chụp hay code
   chưa chạy là nghiệm thu.

## 6. GIỚI HẠN KỸ THUẬT CẦN NÓI ĐÚNG

- AABB là bounds hình học được chiếu theo camera, không chứng minh pixel thật,
  occlusion hay clipping gần/xa chính xác.
- Mỗi `hh play` dùng user directory tạm và dọn sau run để cô lập save. Điều
  này giúp replay sạch; nó không phải bài kiểm persistence qua nhiều lần mở game.
- Bot đo world units; scene 3D thường dùng `--cell 1 --stuck-dist 0.2` rồi tự
  hiệu chỉnh theo scale.
- Receipt Blender là bằng chứng đầu ra và provenance, không thay cho review
  mỹ thuật. Game chất lượng cao còn cần gameplay feel, camera, UI, audio,
  animation, performance, build và playtest người thật.
- Terrain3D/voxel không bắt buộc cho làng/đảo nhỏ: ưu tiên mesh modular hoặc
  heightmap trong Blender. Chỉ thêm Terrain3D khi cần sculpt/paint/LOD/streaming
  diện rộng; chỉ dùng voxel khi xây phá block là mechanic cốt lõi.

## 7. BÀI HỌC ĐÃ GHI LẠI

- Chỉ ghi khóa được yêu cầu không đủ: phải đọc lại và chứng minh mọi setting
  ngoài tập ghi vẫn nguyên vẹn.
- Blender có khác biệt phiên bản ở Action slot; phải kiểm đúng armature/mesh
  được export, không chỉ đếm Action trong file nguồn.
- Evidence phải lấy exit/readback của child thật; không chấp nhận chữ ký hay số
  exit do caller tự điền.
- Test save phải làm hỏng primary và chứng minh fallback; JSON lỗi dự kiến dùng
  `JSON.new().parse()` để không phát ERROR giả.
- Replay phải bắt đầu từ cùng save state và kiểm tra user directory của engine;
  hai run có trace giống nhau nhưng profile khác nhau.
- Strict warnings-as-errors có thể quay lại sau khi dọn cũ: khai báo type rõ và
  tiêu thụ return value của API.
- TSCN phải khai báo subresource trước node dùng nó.
- Trên Windows phải `lstat` metadata không follow trước `realpath`/`exists`,
  nếu không dangling junction gây WinError448 hoặc lọt path.
- Tập trung reproducer ngắn trước; khi đã pass và source không đổi thì không
  lặp lại ma trận dài.
- Đóng plan công cụ không đồng nghĩa game đã đẹp, đủ nội dung, multiplayer ổn
  định hay đạt AAA. Agent game vẫn phải làm slice chơi được rồi mới mở rộng.

## 8. CÁCH DÙNG CHO GAME AGENT VÀ NEXT

Đọc `zdoc/12-10-huong-dan-dung-cong-cu-godot-blender.txt`, tạo brief/design
docs làm nguồn sự thật, rồi làm một slice nhỏ (scene, movement, camera, UI,
audio, save) trước. Mỗi feature đi qua: implement → Play thật → observe/shot
hoặc bot → sửa → ghi kết quả ngắn. Blender tạo và dọn asset; Godot giữ scene,
physics, input, UI và build; agent điều phối nhưng không tự biến công cụ thành
người duyệt chất lượng.

Nếu cần cài kit đã có trong game, phải backup/review rồi mới dùng
`hh kit add ... --replace`; kit không tự nâng cấp file game. Lỗi tool phát hiện
trong dogfood ghi vào `zdoc/12-10-gt11-yeu-cau-tu-agent-game.txt` và sửa theo
change request nhỏ. Android, legal/release approval và claim thương mại là
placeholder chờ owner; không bịa chữ ký, license hay nghiệm thu.
