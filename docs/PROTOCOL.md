## Envelope and framing

- `protocol_ver`: `1.0`
- Transport: TCP `127.0.0.1`
- Framing: NDJSON — one UTF-8 JSON-RPC 2.0 message per line, terminated by LF
- Max line: 4194304 bytes (4 MiB). Over cap → `-32600` / `E_PROTO`, then close that connection (GS-EC-58).
- Slowloris: a line that is not finished in 10s closes the connection.
- Idle timeout: 120s (keep alive with `session.ping`).
- JSON-RPC array batch: **not supported** (server returns `-32600`). Use `transaction.execute`.
- Events are JSON-RPC notifications (no `id`).
- `error.code` is numeric; application codes live in `error.data.app_code`.
- After handshake, identity comes from the connection. Clients do not self-declare `actor_id`.
- Methods marked **[UI]** have `capability: UiOnly` and must be rejected for principal `agent` (`-32001`).

### JSON-RPC `error.code`

| code | meaning |
| --- | --- |
| `-32700` | parse error |
| `-32600` | invalid request / batch / proto |
| `-32601` | method not found |
| `-32602` | invalid params |
| `-32000` | application error (`error.data.app_code`) |
| `-32001` | unauthorized / wrong principal |
| `-32002` | conflict |
| `-32003` | busy / budget |
